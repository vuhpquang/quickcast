# Search Screenshots (Quickcast fork)

A palette sub-screen that shows the screenshots and screen recordings in the macOS screenshot folder
as a grid, newest first, grouped by day. It is reached from the built-in **Search Screenshots**
command (`command:search-screenshots`), its alias, its hotkey, a Compact Shortcuts slot or the
`quickcast://command/search-screenshots` link. There is no feature switch: the command is always
listed, and nothing runs until the screen is open.

## Invariants

- **`Model/` stays Foundation-only.** `Screenshot`, `ScreenshotDetection`, `ScreenshotGrid`,
  `ScreenshotGridColumns` and `ScreenshotTextStore` are compiled by `screenshots-test`.
- **Captures are read where macOS saved them, never copied or indexed in the background.** The
  folder is listed when the screen opens and watched only while it is on screen.
- **The thumbnails have their own cache.** `ScreenshotThumbnails` keeps a 48 MB `ThumbnailCache` so
  scrolling a few hundred captures never evicts Clipboard History's previews, and purges it when the
  screen closes. Quick Look's own disk cache makes a re-open fast.
- **Recognized text is opt-in, local and derived.** It is off by default, excluded from backups and
  from `settings.json`, and lives in `Caches/<bundle id>/screenshot-text.json`, which can be deleted
  at any time.

## Which files are captures

- **The folder** is `com.apple.screencapture`'s `location`, read with `CFPreferencesCopyAppValue`
  every time the screen opens (the Screenshot app's Options menu can move it), with `~` expanded. Unset
  or blank means `~/Desktop`. Only that folder is listed, one level deep.
- **The type decides first:** png, jpg/jpeg, heic/heif, tif/tiff and gif are images; mov and mp4
  are recordings. Nothing else is read further.
- **Then the capture flag:** `screencapture` stamps the Spotlight attribute
  `kMDItemIsScreenCapture` on the file itself as the xattr
  `com.apple.metadata:kMDItemIsScreenCapture` (a binary-plist boolean). It is read directly, so
  Spotlight being off for the folder does not matter.
- **A name is the fallback,** for copies that lost the xattr (AirDrop, a sync, another tool):
  `Screenshot`, `Screen Shot`, `Screen Recording`, their names in the eight shipped languages and
  Vietnamese, plus the custom `name` the user set for `screencapture`, matched as a prefix ignoring
  case, accents and width.
- **Date** is the file's creation date, so cropping a capture later keeps it on its day.

The scan runs in a `@concurrent` function; a newer scan cancels an older one, and a result for a
folder that has since changed is dropped. The FSEvents stream (`FileSystemWatcher`, shared with
File Search) rescans on any change while the screen is visible, so a new capture appears about a
second after macOS writes it. The selection follows the capture it was on, not its index.

Desktop, Documents and Downloads are privacy-protected: the first open may show macOS's folder
access prompt. A denied or missing folder shows "Can’t read …" with where to allow it.

## Grid and keys

The grid is the emoji picker's structure (see [emoji.md](emoji.md#rendering)): day headers with a
count, rows directly under a `LazyVStack` as scroll targets, interaction attached per row, and
`EmojiGridGeometry` for ↑/↓ across day sections. It uses the emoji grid's inset, cell radius and
selection colours. Tiles are 16:10 with the capture fitted inside, a time caption below and a video
glyph on recordings. Thumbnails are generated by `QLThumbnailGenerator` in a `.task` per tile, so
only realized rows ask for one and a row scrolled away cancels its request.

Columns are three to six, four by default (`screenshotGridColumns`, settings.json
`fileSearch.screenshotColumns`, kept out of backups). ⌘+ / ⌘- / ⌘0 zoom like the emoji grid, through the
same panel chord, and only for the open screen.

| Action | Key | What it does |
| --- | --- | --- |
| Paste to … | ↵ | Clipboard History's convention: the image data plus its file URL into the app behind the palette |
| Open | ⌘↵, ⌘O | the default app, through `NSWorkspace`'s asynchronous open |
| Copy Image / Copy File | ⇧⌘C | the same pasteboard write without pasting; a recording is copied as its file |
| Copy Path | ⌃⌘C | the path as text; the palette stays open |
| Show in Finder | ⌘F | reveals and dismisses |
| Actual Size / Zoom In / Zoom Out | ⌘0 / ⌘+ / ⌘- | grid density for this session |
| Move to Trash | ⌃X, ⌘⌫ | asks first through `DialogController`, then trashes off-main |

The copies are not marked with `ClipboardManager.internalType`, so a pasted or copied capture
enters Clipboard History like any other copy. **There is no Quick Look**: a `QLPreviewPanel` takes
key, and the palette hides on `windowDidResignKey` — the same reason Search Files has none. A tile
is already a preview, and ⌘↵ opens the capture in Preview.

## Search

Every typed word must appear, in any order, in the capture's name, its date or its recognized text,
ignoring case and accents. The date is searchable in the user's locale and in English — the full
date, the abbreviated month and weekday, and `yyyy-MM-dd` — so `march`, `mon` and `2026-03-02` all
work. Those strings are formatted once per scan, and the results are memoized on the query, the
library revision and, while text search is on, the text store's revision.

## Text in screenshots

**Search text in screenshots** (`screenshotTextSearchEnabled`) is off by default. While it is on and
the screen is open, `ScreenshotsCoordinator.recognizeText()` reads the newest unread image after a
one-second pause, then the next, 250 ms apart, through Clipboard History's bundled
`ClipboardTextHelper` (`ClipboardTextWorker.extract(at:isPDF:executable:)`), so Vision's memory leaves
with the child process and the same size and time limits apply. Closing the screen cancels it.
Text is stored folded, keyed by modification date, so an edited capture is read again; a failure is
skipped for the rest of the session. The cache is written every ten captures and when the run ends,
and drops captures that left the folder.

## Validation

`screenshots-test` covers detection by flag, name, localized and custom prefix; folder resolution;
order and day grouping; date and text search; column zoom; grid navigation across days through
`EmojiGridGeometry`; and the text store's folding, invalidation, pruning and file round trip.
